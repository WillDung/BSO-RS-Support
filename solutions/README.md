# Solution source

`solutions/` is the canonical local source boundary for `os_sr_bso_rs_support`. It combines the PAC-unpacked structural metadata with the existing authored Candidate Core and Candidate Console projects. Candidate Console web-resource payloads have one authoritative source in [CandidateConsole/WebResources](CandidateConsole/WebResources); the PAC packer stages those files alongside their metadata without creating a second tracked payload copy.

Use [`Build-BsoRsPortableSolution.ps1`](../scripts/Build-BsoRsPortableSolution.ps1) to create and round-trip-check an unmanaged source archive outside the repository. Do not pack the folder directly. The guarded packer deliberately excludes the 50 inactive `ProtectCandidateCore` registrations, both assembly roots (the signed legacy assembly is rollback-only; the active package-backed assembly is updated separately), and the temporary `os_sr_devcs` API. The complete 72-root export mapping and each retained/excluded disposition are recorded in [SOLUTION_COMPONENT_INVENTORY.json](../docs/SOLUTION_COMPONENT_INVENTORY.json).

The checked-in environment configuration remains `UNCONFIGURED`, synthetic-only, Candidate Core disabled, fallback disabled, and diagnostics Off. [release-profiles.json](release-profiles.json) defines portable DEV/TEST/PROD policy only; target URLs and identifiers must be supplied externally after approval. Release-profile configuration generation must keep Candidate Core enabled, synthetic-only mode on, fallback disabled, and diagnostics Off.

The accepted unsigned `os_sr_cact_pkg` artifact and PAC `pluginpackage.xml` metadata are retained as the existing PluginPackage component and hash-pinned in [RELEASE_ARTIFACTS.json](../docs/RELEASE_ARTIFACTS.json). Managed release creation and Test rehearsal remain blocked pending an approved Test environment and managed package built from reviewed source. Do not import to Test or Production, assign roles, connect to an environment, create or update a package, change a handler/guard, commit, or push under this source-preparation scope. See [ALM Deployment](../docs/ALM_DEPLOYMENT.md), [Test Rehearsal Plan](../docs/TEST_REHEARSAL_PLAN.md), and [Rollback Plan](../docs/ROLLBACK_PLAN.md).
